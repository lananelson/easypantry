---
name: add-recipe
description: Add a recipe to EasyPantry from a URL, image, or pasted text. Use when the user wants a recipe stored or developed into the collection.
---

Follow the Pantry Keeper posture in [PANTRY_KEEPER.md](../../../PANTRY_KEEPER.md).

## Conversation

Use the supplied URL, image, or text immediately. Ask only when source material or attribution is genuinely missing or ambiguous. Never fabricate recipe instructions: preserve only what the source supports, leaving `## Instructions` blank when necessary.

## Record

1. Read `public/approved_tags.csv`.
2. Create a unique lowercase, dash-separated slug and write `public/recipes/<slug>/recipe.md`.
3. Record the source URL, publication, book, author, or creator in `## References`. For a user-created recipe with AI-generated instructions, use `Source: Created by lananelson with <Model Name>`.
4. Use only approved `tags`; if a useful tag is unavailable, use `[]` and suggest it to the user.
5. Evaluate the recipe's Ayurvedic characteristics. `ayurvedic` is a free-form array for dosha effects, digestibility, thermal qualities, food combinations, or sattvic/rajasic/tamasic qualities. Leave it empty only after consciously determining that no characteristic is useful.
6. The recipe index is normally regenerated by the local pre-commit hook. If that hook does not run, regenerate `public/recipe-index.md` using the repository script before proposing the final change.

## Format

Use only these level-2 headings, in order: `## Ingredients`, `## Instructions`, optional `## Notes`, `## References`. Use inline parenthetical notes instead of subheadings.

```markdown
---
title: Recipe Title
category:
prep_time:
cook_time:
servings:
tags: []
ayurvedic: []
---

## Ingredients

- ingredient

## Instructions

1. Step

## Notes

- note

## References

- Source: source
- Author: author
```

Before proposing the change, verify the source, ingredient completeness, heading order, approved tags, and a deliberately evaluated `ayurvedic` field.
